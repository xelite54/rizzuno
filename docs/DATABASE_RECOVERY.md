# Database recovery

Operator must verify in Supabase: plan backup availability, daily backup schedule, last successful backup, retention duration, encryption/access controls, eligible PITR window and recovery granularity. Define and approve RPO/RTO. See [Supabase backups](https://supabase.com/docs/guides/platform/backups). A healthy database is not proof that backups exist. Object Storage bytes require their own backup/export strategy; a Postgres backup does not back up those files.

Restore drill (isolated project first): choose a recorded recovery point, restore using the project's supported backup/PITR workflow, verify migration ledger, row counts, constraints, security query, profile references, representative friend-message/reply history, legal acceptance and moderation audit records. Check Storage object existence separately. Run authenticated web/realtime tests against the isolated restoration. Record duration, lost-data window and approver. No restore drill has been performed by this change.

Actual recovery: disable web mutations and OAuth admission, stop ALL Railway realtime replicas and scheduled/administrative writers, and prevent old deployments reconnecting. Drain connections. Preserve the damaged database for restricted investigation. Restore into an isolated target where possible; verify before changing both server DATABASE_URLs and CA settings. Never print connection strings. Start a single realtime replica, test readiness and role permissions, then reopen traffic gradually. Clear/recreate ephemeral Redis state to avoid references to rolled-back rooms/invitations. Reconcile reports/legal/billing writes after the recovery point with counsel and operators.

For a bad migration: first determine whether its transaction committed. An uncommitted migration needs a forward correction and retry. A committed destructive migration requires a reviewed forward repair or restore/PITR. Do not delete migration ledger rows to conceal failures. Restore point selection may lose subsequent valid writes; document that tradeoff before cutover.
