# Persistent homepage controls

The four self-panel controls were descendants of `signedIn && legalAccepted && onboarded && !restriction` in `MatchStage`. This was an unmount condition, not a CSS animation. In the browser regression, transitioning an admitted account to a temporary realtime restriction removed all four controls while the homepage's React Profiler still reported one mount. `useMatchmaking.announce()` clears restrictions on a successful ticket response, so retry/rejection cycles could repeatedly mount and remove the group. Legal checking and profile hydration could also remove it through the same gate.

The controls now occupy unconditional positions in the component tree. Profile, friends, microphone, and chat availability use button `disabled` attributes. Their placement follows the existing home/call layout, not the duplicate camera/legal/restriction-dependent `onHomeScreen` calculation. The old 600 ms visibility-return animation suppression timer was removed. The signed-out mobile preview has a 112 px minimum width so its newly persistent microphone/chat buttons fit. Existing icons, overlays, action callbacks, and room-specific chat-panel keys remain.

The two-second hello retry, five-second friends refresh, and fifteen-second readiness watchdog remain recovery/presence mechanisms; they no longer mount or remove personal controls. There is no replacement visibility timer or CSS hiding workaround.

Run `npm run test:homepage:browser` (Chrome required; override `CHROME_PATH` where necessary). The default 180-second test renders the actual `MatchStage`, controls, styles, and React effects with fixture service hooks. It cycles initial loading, signed-out, idle, auth refresh, legal checks, onboarding hydration, camera off, searching, matched, skipped, reconnecting, restrictions, presence, and paused states every two seconds. Desktop and mobile viewports alternate. It records original DOM identities, subtree removals, duplicate/missing buttons, computed visibility and clipping on animation frames and mutations, React Profiler commits/mounts, and console errors. Results and a screenshot are saved in the printed temporary artifact directory. Shortening `HOMEPAGE_HOLD_MS` is useful for debugging but does not establish several-minute stability.

This controlled browser regression does not authenticate with Google or diagnose live production network failures. `npm run test:webrtc:browser` separately exercises real browser media/signaling with fixture accounts.

Local verification on 2026-09-22: the original source failed the realtime-restriction transition with all four controls missing and one homepage mount. The fixed source passed 181,179 ms (3 minutes 1 second), 17,411 frame/DOM samples, 174 React commits, one homepage mount, unchanged control DOM references, all 15 scenarios, and zero console errors. Desktop/mobile layouts alternated. The test checked all four controls even during initial auth loading and signed-out states.
