# Approved images and migration

Provision a **private** Supabase Storage bucket, server-only IMAGE_STORAGE_KEY, HTTPS IMAGE_STORAGE_URL and IMAGE_STORAGE_BUCKET on web. Restrict key access and configure bucket MIME/size limits (WebP, 3 MB). Do not set browser bucket policies or make the bucket public. Storage API must remain enabled even if Data API is disabled. Consult [private asset downloads](https://supabase.com/docs/guides/storage/serving/downloads).

Uploads are bounded, magic/MIME checked, fully decoded with Sharp and re-encoded to WebP, stripping metadata and trailing payloads. Animated source images are rejected so an unreviewed frame cannot escape moderation. Existing UI creates still images. Sightengine and any explicitly configured specialist inspect normalized bytes before upload. Public bucket configuration is rejected. Generated UUID keys only; full read-back SHA-256 verification precedes DB reference creation. Existing profile/post columns carry same-origin URLs; legacy data URLs remain readable. Chat images remain transient normalized images and are not moved into durable storage.

The authenticated media route serves only objects still referenced by a non-deleted/non-banned profile/post. Private objects from failed writes are not published. Removed objects stop being served, but physical orphan deletion is deliberately not automatic until operator retention is approved. Inventory unreferenced objects against a consistent DB snapshot with a grace period; recheck before deleting. Account exports need associated object delivery by the privacy operator; URLs alone are not a complete image export.

Run `npm run images:migrate` with a protected environment for a bounded dry run. After backup, use `npm run images:migrate -- --apply`, optionally IMAGE_MIGRATION_LIMIT (1–1000). It rechecks moderation, uploads, verifies, then updates only if the original DB value still matches. Failure/rejection leaves original bytes untouched. Rate limits still apply; run in small batches and investigate rejected legacy content in the moderation workflow. Never delete old content before successful upload verification. Do not log rows/image bytes. Actual provider/bucket upload, legacy migration and object backup still require operator verification.
