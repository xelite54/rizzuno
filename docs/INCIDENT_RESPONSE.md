# Incident response

1. Record start time, affected release, safe symptom counts and incident owner. Check readiness, database, Redis, coordinator changes and provider status. Do not copy user content/secrets into incident logs.
2. For database compromise, restrict application ingress and realtime traffic, revoke exposed credentials and Data API access, preserve access/audit evidence under restricted custody. A secret in Git history must be rotated, even after removing the file.
3. For split-brain/stream-gap symptoms, stop admission, drain/stop ALL realtime writers, restore Redis health, start one coordinator and verify readiness before reopening. Active calls are interrupted; do not promise seamless recovery. Reports/blocks already committed to Postgres survive; unacknowledged commands may require retry.
4. Underage reports go first in `/admin`. Review context, suspend access where justified, record reason and prior state, and escalate to the designated trained safety lead. For credible immediate danger use the operator's legally reviewed emergency procedure and appropriate authorities. Avoid downloading, forwarding or duplicating suspected illegal imagery. Retain only necessary metadata in restricted systems; counsel determines preservation/reporting duties.
5. Sightengine is generic content screening. `severeContentCapability().state` is `not configured` until an approved specialist adapter is registered. Never treat nudity confidence as a child-content finding. Before enabling a hash/specialist provider, review contract, applicable reporting duties, geography, evidence minimization, false-positive handling, access controls, retention and outage behavior. Integrate only through `SevereContentProvider`; test fail-closed behavior and truthful capability reporting.
6. Reopen gradually after tests and a monitored canary. Record unresolved risk and corrective actions. Notify users/regulators only through operator-approved processes.

Age gate is self-attestation: 18 or a higher local age of majority. `AgeAssuranceProvider` is only an optional server adapter interface, not an integration or a compliance claim. Review each jurisdiction before expansion. Prefer provider-held verification with a bounded assertion; Rizzuno should not collect government-ID images.
