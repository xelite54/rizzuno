# Provider-backed staging validation

Local fixture results are not mass-production proof. Do not choose launch concurrency from `docs/LOAD_TEST_RESULTS.json` alone. This plan must be executed against isolated, production-shaped staging resources, with synthetic adult operator-controlled accounts and a documented budget/admission limit. No destructive or load test is authorized against production by this document.

## Target isolation and controls

Use dedicated staging hostnames, Postgres project/pooler/database, private Storage bucket, Redis instance and TURN credentials. Verify identifiers in provider consoles; never reuse production signing secrets, Google users' sessions or database credentials. Freeze production origins in the test plan and verify staging DNS points to separate resources. Set spend/rate caps and an emergency stop owner before testing.

The local `npm run test:load` refuses external endpoint/database parameters and stays fixture-only. The new `npm run test:staging:ws` requires `LOAD_ENVIRONMENT=staging`, `LOAD_WRITES_APPROVED=true`, HTTPS `STAGING_HTTP_ORIGIN`, WSS `STAGING_WS_URL`, and an exact `STAGING_TARGET_ACK` equal to the web origin. Both hosts must contain a distinct `staging` label/segment; credential-bearing URLs are rejected. It refuses signing secrets and DATABASE_URL. Before opening sockets it requires a matching authenticated staging marker from `/api/staging/ready`.

On staging only, set `DEPLOYMENT_TIER=staging`, `DEPLOYMENT_REVISION` and a random server-only `STAGING_PROBE_SECRET` of at least 32 characters. The same probe secret must be supplied to the harness, never public environment variables. Outside staging the marker is 404; production validation rejects a staging probe secret unless the tier is staging. Do not install this secret on production. Regional access checks still apply.

Provide `STAGING_TICKETS_FILE`, a private local JSON array of 4–100 fresh realtime tickets obtained through ordinary signed-in staging accounts that accepted current legal versions and selected genders. Use an even number, equally split by persisted gender. The harness uses real WebSockets, matching and report writes, then checks rematching, with a hard one-minute cap. It does not fabricate Google identities or bypass acceptance. Files contain short-lived credentials: keep outside git, restrict permissions, remove after use. The operator must monitor and dispose of synthetic report data under approved staging retention. This harness is control-plane-only; it explicitly reports media/TURN as untested.

## Required matrix

Record release SHA, topology, actual provider/region/tier, configuration review reference, account count, concurrency/ramp, duration, error counts and raw metric artifact locations for every run. Define pass/fail thresholds and a conservative launch cap *before* executing the test; do not retroactively relabel failures as passing. Stop on increasing queue age, pool exhaustion, dropped media, moderation write failures or exhausted spend caps.

| Area | Defined exercise and evidence |
| --- | --- |
| Real Postgres/pooler | Run migrations and database privilege SQL against the staging owner. Verify pooler mode/TLS. Drive signed-in profile, friend, chat, report, legal and privacy flows with actual rows. Capture p50/p95/p99 query latency, waiting/active connections, timeouts, deadlocks and pool saturation. Inspect EXPLAIN on representative synthetic volume. |
| Redis / multiple realtime instances | Use at least two actual gateways with the configured coordinator/Redis. Distribute clients across instances; record coordinator identity/fencing, stream lag, event backlog and Redis latency. Kill/restart one staging coordinator and observe bounded recovery without double matches. |
| WebSocket traffic | Run `test:staging:ws` with normal staging tickets. Ramp cohorts only within the approved cap. Observe successful ready/matched/report acknowledgments and persisted report rows; verify no real-account data is present. |
| Real WebRTC media | Use signed-in staging Chrome and physical desktop/mobile browsers on separate networks. Send moving video and audible audio in both directions; verify actual decoded/sent frame counters, senders/receivers and selected ICE pair using getStats. Hold for the approved duration under concurrent WS/DB load. Local `test:webrtc:browser` remains a regression test, not this evidence. |
| TURN fallback | Block direct UDP paths in the test network or force relay in a dedicated staging browser probe. Use fresh `/api/realtime/turn` credentials; `tests/browser/verifyProductionTurn.mts` can run a separately authorized bounded probe against staging allowlisted hosts. Confirm selected candidate type `relay`, bidirectional media, TCP/TLS fallback and expiry. Record actual relay bandwidth and provider limits/cost. No static browser credentials. |
| Reconnect / skip / rematch | Disconnect network, foreground mobile tabs, restart a gateway and expire a ticket; verify renewed authenticated tickets, current acceptance, no duplicate ownership, recent-partner cooldown and eventual eligible rematch. Reuse the recovery scenarios in `tests/browser/README.md` against staging. |
| Moderation/report writes | Test approved harmless image fixtures, rejected format/content fixtures and simulated provider outage. No illegal samples. Verify fail-closed behavior, urgent underage queue, snapshots, deduplication, trained-role permissions and no evidence exposure through profile/media/export routes. |
| Image delivery | Upload approved synthetic images to the actual private bucket. Test authenticated delivery, unreferenced/erased denial, private bucket checks, read-back integrity, orphan discovery, retries and Storage purge after holds release. Measure bandwidth, request latency and provider errors. |
| Memory/CPU | Collect per-instance CPU, RSS, event-loop delay, socket count and restart count throughout ramp, hold, reconnect and drain. Check that room/chat snapshots disappear after room end and memory returns toward baseline. |
| Retention/privacy | Exercise bounded batches, reply dependencies, active holds, pre-change preservation, admin erasure, deletion retry, identity denial and backup restore in isolation. Check scheduling heartbeat and manual-review backlog alerts. |
| Regional gates | Approved country works; disallowed/unknown country and forged country headers cannot issue tickets. Check custom/preview domains and direct realtime endpoints. Remove a country and drain existing connections. |

Repeat planned cohorts/soak durations under ordinary and degraded conditions (provider latency, gateway loss, packet loss and TURN-only routing). Retain failed as well as passing artifacts. No repository fixture proves real provider capacity; all rows of this matrix remain external staging evidence until actually executed. The remote WS probe alone is not a scalable media load generator. An operator-owned browser fleet and resource monitoring are required for media/TURN scale validation.
